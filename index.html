04 / APPLICATIONS

Where this fits

  • Home environment monitoring — track a room's comfort levels and get an early read on damp, heat, or poor ventilation.
  • Server/electronics cabinet watch — flag conditions that risk hardware before a fault happens.
  • Greenhouse or grow-tent monitoring — keep humidity and light within a target band for plants.
  • Lab or storage rooms — log conditions for equipment or materials sensitive to temperature swings.
  • Coursework and portfolio demo — a genuine full-stack slice: sensor logic, data flow, and a console UI, in one place.

How it would run for real

  • ESP32 reads DHT22 (temp/humidity) and an LDR (light) on a timer.
  • Readings are sent as JSON over Wi-Fi, either to a lightweight HTTP endpoint or an MQTT broker.
  • A backend stores each reading with a timestamp for the history table.
  • This dashboard polls or subscribes to that feed and renders it live, exactly as it does now with simulated data.
Advantages & Disadvantages
05 / TRADE-OFFS

Advantages

  • Cheap to build — an ESP32 and two sensors cost a fraction of commercial monitoring hardware.
  • Remote visibility — check conditions from any browser instead of walking over to a room.
  • Extensible — same pattern scales to more sensors (CO₂, soil moisture, sound) without redesigning the dashboard.
  • Fast to demo — the web layer works standalone, so it can be shown before hardware is finalized.

Disadvantages

  • Depends on Wi-Fi — a dropped connection means a gap in the data, not a graceful fallback.
  • No alerting yet — right now it's a dashboard, not a system that pages you when a threshold is crossed.
  • Single-node design — this version reads one board; monitoring multiple rooms needs a proper backend and device registry.
  • Simulated data here — the live demo doesn't reflect real sensor noise or hardware failure modes.
